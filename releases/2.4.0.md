# Smart Home Dashboard 2.4.0

## Settings authentication

- Opening Settings now always requires an administrator sign-in.
- After the correct administrator PIN is entered, Settings opens on the normal System page.
- If the administrator session expires while Settings is open, protected Settings pages request authentication again instead of silently allowing access.

## Customisation

- Added a dedicated **Customisation** category.
- Home Overview configuration now lives in Customisation.
- Administrators can add, remove and reorder Home overview widgets, including live camera widgets.
- Room visibility and room order are also managed from Customisation.

## Accessibility

- Replaced the separate Themes category with a new **Accessibility** category.
- Accessibility includes all eight dashboard themes:
  - Midnight
  - Graphite
  - High Contrast
  - Warm
  - Ocean
  - Forest
  - Violet
  - Slate
- Added font selection:
  - System
  - Accessible Sans
  - Serif
  - Monospace
- Added dashboard-wide text-size choices from Small through Maximum.
- Font and text-size preferences are saved in dashboard configuration and apply across the whole interface.

## Failed update cleanup flow

- **Delete Failed Update Files** now asks for confirmation before deleting anything.
- If administrator authentication is required, the PIN prompt stays within the update workflow.
- After authentication, the dashboard remains on the Updates page instead of sending the user to Administrator settings.
- Multiple administrator accounts can be selected in protected-action PIN prompts.


## New verified update engine

- Replaced branch-ZIP updating with one versioned update package selected by `updates/latest.json`.
- Every update package is SHA-256 verified before it is extracted or built.
- The new Docker image is built from a staging directory while the installed dashboard continues running unchanged.
- The current Docker image and application files are preserved as rollback material before restart.
- After restart, the helper verifies `/api/health` reports the expected version.
- If the new dashboard fails health verification, the previous image and application files are restored automatically.
- Failed downloads and staging files can be safely deleted and a retry always starts fresh.
- Version 2.4.0 removes the old compressed runtime-payload layout and returns the GitHub source to normal `server.js`, HTML, CSS and JavaScript files.
